# 统一浏览量统计设计

## 目标

将文章和每日一问的浏览量统一为“同一匿名访客、同一内容、同一北京时间自然日最多计数一次”，消除读取接口副作用、并发重复计数、日志与累计值分裂、每日一问批量刷量和缓存展示滞后。

## 统计语义

- 统计单位是每日独立浏览，不是每次 HTTP 请求，也不是登录用户数。
- 内容类型仅允许 `article` 和 `daily_question`。
- 前端生成并持久化随机匿名 ID，通过 `X-Visitor-ID` 请求头发送。
- 后端不保存匿名 ID 或原始 IP；使用 JWT secret 作为 HMAC-SHA256 密钥。匿名 ID 缺失或不合法时，以客户端 IP 作为兜底输入。
- `X-Visitor-ID` 加入 CORS 允许请求头；Gin 只信任配置的反向代理网段，避免任意请求头伪造 IP 兜底身份。
- 日期统一按 `Asia/Shanghai` 计算。

## 数据与一致性

新增 `content_view_events`：`content_type`、`content_id`、`visitor_key`、`view_date` 和创建时间。数据库唯一索引覆盖前四列。

记录浏览必须在一个数据库事务内完成：先以 `ON CONFLICT DO NOTHING` 插入事件；只有实际插入一行时，才对目标内容的 `view_count` 原子加一。目标不存在、未发布或每日一问日期晚于今天时，整个事务回滚。接口返回 `counted` 和最新 `view_count`。

旧 `visit_logs` 保留为历史数据，不再写入。文章和每日一问已有 `view_count` 作为上线前累计基线继续保留。切换当天的“今日浏览量”只统计新事件，部署后的下一个自然日起口径完整一致。

## API 与前端

- `GET /articles/:slug`、每日一问 latest/date/all/previous/next 全部变为纯读取，不再增加浏览量。
- 新增 `POST /api/v1/views`，请求为 `{content_type, content_id}`，匿名身份来自请求头或 IP 兜底。
- 文章详情成功加载后记录一次浏览，并用接口返回值更新当前文章的展示值。
- 每日一问 `/all` 直接返回完整问题数据，去掉逐条详情请求；使用 `IntersectionObserver` 在题目首次进入视口时记录浏览，每个页面生命周期只调用一次。
- 文章列表缓存允许最多五分钟的统计展示延迟；文章详情和当前可见每日一问使用记录接口返回的权威值即时刷新。

## 错误处理与安全边界

- 计数失败不影响正文读取，但前端不伪造本地加一。
- 不支持的内容类型、无效 ID、无效匿名 ID返回参数错误。
- 目标不存在或不可公开访问时返回资源不存在，且不留下事件。
- HMAC 只降低原始标识泄露风险，不等同于反机器人或防恶意伪造匿名 ID；限流和机器人识别不在本次范围。
- `TRUSTED_PROXIES` 显式配置可提供真实客户端 IP 的代理；配置非法时禁用代理请求头解析并退回直连地址。

## 验证

- SQLite 仓库测试验证首次计数、同日重复、次日再次计数、并发重复、无效目标回滚和两种内容类型。
- 服务/控制器测试验证身份派生、请求校验和错误映射。
- Node 单元测试验证匿名 ID复用、请求头注入和页面生命周期去重辅助逻辑。
- 运行目标 Go 测试、全量 Go 测试、前台构建和静态差异检查；MySQL/Redis/浏览器实测作为部署前独立验收。
